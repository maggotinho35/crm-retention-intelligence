# Data dictionary (synthetic)

Generated by `src/crm_bi/data_generation.py` with seed 42. No real customer data is used.

## data/customers.csv (1,200 rows)
| Column | Meaning |
|---|---|
| customer_id | Synthetic identifier (C100000 onward) |
| segment | young_digital, family, mass_affluent, retiree |
| age, tenure_years | Years |
| monthly_logins, monthly_transactions | Engagement over the last month |
| avg_balance | EUR |
| num_products | Count of products held |
| complaint_count_12m | Complaints in the last 12 months (0 to 5) |
| had_fee_increase | 1 if the customer had a recent fee increase |
| churned | 1 if the customer left (target; about 24.7%) |

## data/complaints.csv (one row per complaining customer)
customer_id, complaint_text (free text with varied phrasing and some deliberately vague complaints), true_category (hidden label used only for evaluation and for the supervised stage that simulates agent tagging).

## data/transactions.csv
One row per customer: 0/1 holding flags for eight products (checking, savings, credit card, mortgage, personal loan, investment fund, insurance bundle, mobile wallet) and the segment.

## How the generator was calibrated
Segment sizes, overall churn (24.6% target), product-holding patterns and complaint-theme shares follow the portfolio's dataset appendix. Churn is drawn from a logistic function of engagement, tenure, complaints, fee increase, product count and segment, with noise, so it is learnable but not deterministic. A fee increase raises both complaint counts and the chance of a billing complaint. This is a re-implementation, so individual rows differ from the original.
